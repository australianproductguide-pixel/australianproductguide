## Delete-account security

Public user-bound rows use `ON DELETE CASCADE` to the Auth identity. The function does not accept an arbitrary target user ID from the browser.

**Arbitrary-target deletion design review:** PASS.

## Leaked-password protection decision

Current state: disabled; Supabase organisation on Free; Security Adviser warning remains.  
Benefit: blocks passwords known to be compromised via Supabase's leaked-password screening.  
Consumer impact: compromised passwords would be rejected when setting/changing a password.  
Compatibility: low expected impact on legitimate account journeys; existing v36.1 password-strength enforcement remains separate.  
Cost: enabling requires a paid Supabase tier, creating recurring cost.  
Rollback: disable the feature and reassess plan dependencies; any plan downgrade must consider unrelated Supabase requirements first.  
Recommendation: **do not silently upgrade solely for this control; owner approval is required before any paid-plan change.**

Status: **BLOCKED — OWNER APPROVAL + PAID PLAN IMPLICATION**.
